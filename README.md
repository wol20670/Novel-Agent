# Novel-Agent

오프라인에서 동작하는 **Ren'Py 비주얼노벨 제작 보조 웹앱** (Vite + React + TypeScript).
엑셀/텍스트로 스토리를 입력하면 → 장면을 자동 분석 → 캐릭터·표정·위치 결정 → 배경·BGM·스프라이트
**에셋 업로드**(ChatGPT/Suno 등 외부 도구 제작분) → 인앱 미리보기로 검수/승인 → **배포 가능한
Ren'Py 프로젝트**로 내보낸다.

## 작업 흐름

```
1. 스토리 입력  → 2. 장면·캐릭터 분석 → 3. 에셋 업로드    → 4. 미리보기·승인 → 5. ZIP/폴더 출력 → 6. 배포 빌드
   (엑셀/텍스트)    (표정·위치 자동)     (배경·BGM·입화)     (인앱 플레이어)     (Ren'Py 프로젝트)   (실행 파일)
```

- **이미지·음악은 앱이 생성하지 않는다.** 배경·캐릭터 입화·CG는 ChatGPT 등에서, BGM은 Suno 등에서
  직접 만들어 앱의 **에셋 탭**에 업로드한다. 업로드 안 한 이미지는 Canvas 임시 이미지로 자동 채워져
  미리보기·ZIP이 항상 동작한다(단 BGM은 임시 대체가 없다 — 업로드 안 한 씬은 음악 없이 출력됨).
- **OpenAI 키(선택)**: 이미지 생성이 아니라 **대본 자동 번역**(영/일) + **AI GUI 테마 생성**에만 쓰인다.
- **Typecast 키(선택)**: **성우(TTS) 음성 생성**에 쓰인다(대사별/캐릭터별). BYO 키, 잔여 크레딧 표시.
- **자체 제작 풀 GUI**: 메인/게임 메뉴·저장/불러오기·설정·기록·도움말·정보·**크레딧** 등 전 화면 직접 정의(기본은 외부 GUI 이미지 의존 0). 장르 프리셋 5종 + AI 테마 생성. 원하면 **타이틀 로고·메인 메뉴 버튼을 이미지로 교체**(업로드).
- **표정·의상 편집**: 표정 세트를 추가·이름변경·삭제하고, 캐릭터마다 의상을 만들어 **대본 `#복장` 태그로 장면별 의상**을 입힌다(의상마다 표정 세트 별도).

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 타입체크 + 프로덕션 빌드 (dist/)
npm run typecheck  # tsc --noEmit
npm run test        # vitest (파서·번역·아이템 단위/통합 테스트)
```

> ⚠️ `vite dev` 개발 서버에는 알려진 취약점(GHSA-67mh-4wv8-2f99 등)이 있어 **공용/신뢰할 수 없는 네트워크에서 노출 금지**.
> 배포하는 프로덕션 빌드(`dist/`)에는 영향 없음.

## 캐릭터 · 표정 · 배치

### 표정 (감정) — 편집 가능 + 자동 추론 + 수동 선택 + 미리보기
- 대사에 표정을 안 적어도 **문맥(키워드·문장부호·배경)으로 표정을 자동 추론**한다(`src/generators/emotion/`, 오프라인·결정적). 기본 표정 6종: 기본·기쁨·슬픔·화남·놀람·수줍음.
- **표정 세트 편집**: 에셋 탭 `😀 표정 세트` 에서 표정을 **추가**(예: 당황·황당·윙크)하거나 **이름변경**(화남→황당)·**삭제**할 수 있다(전 캐릭터 공통). `'기본'` 은 스프라이트 기준 입화라 고정. 이름을 바꾸면 이미 업로드한 캐릭터 입화·대사 표정도 자동으로 이전된다.
- 화자 뒤에 `(표정)` 을 명시하면 그 값이 우선(`주인공(기쁨): 안녕!`). 커스텀 표정 이름도 그대로 인식한다.
- **장면 카드에서 대사 줄마다 표정을 수동 선택** 가능(자동 추론 위에 덮어쓰기). 직접 지정한 줄은 강조 표시된다.
- 우측 **미리보기 패널의 인앱 플레이어**로 ▶ 대사를 넘기며 **캐릭터·표정·의상·위치를 Ren'Py 내보내기 전에 확인**한다(스프라이트 없으면 임시 이미지로 표시). 표정은 Ren'Py 처럼 다음 변경 전까지 유지된다.

### 의상 (복장) — 캐릭터별 의상 + 배경 키워드 자동 지정 + 장면별 `#복장`
- 캐릭터마다 **의상**을 추가할 수 있다(에셋 탭 캐릭터 카드의 `👗 의상` 탭). 각 의상은 **복장 묘사**(참고 메모, 예: 흰 비키니 수영복)와 **표정 세트를 따로** 가진다. `'기본'` 의상이 기본값.
- `#복장 캐릭터:의상` 은 **그 `#S` 장면(자동 분할된 비트 포함)에만** 적용된다 — 다음 장면으로 넘어가면 이어지지 않으므로, 장면마다 반복해 적어야 한다.
- 적는 **위치**에 따라 적용 범위가 다르다: 장면 맨 앞(첫 대사/지문보다 앞)에 적으면 **그 장면의 시작 의상**, 장면 도중에 적으면 **다음 대사/지문 줄부터** 갈아입는다(한 장면 안에서 여러 번 갈아입을 수 있다). `#아이템`·`#CG`·`#BGM` 마커는 이 예약을 소비하지 않으므로, 그 사이에 끼어 있어도 다음 대사/지문에 적용된다.
- 장면 수십~수백 개에 매번 `#복장`을 적기 힘들 때는 **배경 키워드 규칙**을 쓴다(에셋 탭 캐릭터 카드 → 의상 선택 시 나오는 `🏷 이 의상을 입을 배경 키워드`): 배경 이름에 그 키워드가 들어간 모든 장면에 자동으로 해당 의상이 입혀진다(예: 배경 이름에 "카페"가 들어가면 카페 의상). 여러 규칙이 겹치면 **위에 있는 규칙이 우선**(↑↓로 순서 조정).
- 특정 장면 하나만 규칙과 다르게 하고 싶으면 **장면 카드의 `👗 의상`** 에서 그 캐릭터의 의상을 직접 골라 규칙을 덮어쓴다(대본의 `#복장`과 동일한 우선순위 — 장면 직접 지정 > 배경 키워드 규칙 > 기본).
  ```
  #S 바닷가
  #배경 해변
  #복장 한지수:수영복
  한지수(기쁨): 바다다!
  ```
- 의상별 표정 세트는 각각 업로드한다. 그 장면 의상에 해당 표정 스프라이트가 없으면 **기본 의상으로 자동 폴백**.

### 주인공(내레이션 전용) 화자
- `주인공`·`나`·`플레이어` 는 **내레이션 전용**으로 자동 분류 — 화면에 스프라이트를 세우지 않고, 에셋 탭 캐릭터 목록·위치 계산·표정 라벨에서 제외된다(대사 이름표·분기에는 정상 참여). 비주얼노벨 1인칭 주인공 관례를 반영.
- 에셋 탭에서 일반 캐릭터를 "내레이션 전용으로" 전환하거나 되돌릴 수 있다.

### 화면 배치
- 한 장면에 서는 캐릭터(주인공 제외)는 **첫 등장 순서로 가로 위치 자동 배정**: 1명=가운데(50), 2명=좌우 대칭(30·70), 3명+=균등 분배.
- 위치는 **등장할 때마다 점진적으로 재계산**된다 — 혼자 등장 중엔 중앙, 두 번째 캐릭터가 등장하는 순간 이미 서 있던 캐릭터도 즉시 고정 위치(좌/우)로 스냅 이동한다(표정·의상은 유지).
- 크기는 어떤 해상도 이미지든 `transform vn_char` 가 화면 높이 90%로 `fit` 정규화(머리 잘림 방지).
- **배경**은 `transform vn_bg` 가 `fit "cover"` 로 화면을 꽉 채운다(업로드한 어떤 크기 이미지든 동일, 검은 띠·왜곡 없음).

### 합동 대사 (둘 이상이 동시에)
- `한지수, 강민주: 짠!` 처럼 화자를 `, & / · 、 ＆` 로 묶으면 **합동 대사**가 된다. 멤버 전원의 스프라이트가 함께 서고, 이름표는 묶음 라벨(`한지수 & 강민주`)로 표시된다(`cj_N` 합동 Character).

## 에셋 워크플로우 (배경 · 캐릭터 입화 · CG · BGM)

이미지·음악은 **ChatGPT / Suno 등 외부 도구에서 직접 만들어 업로드**한다. 앱은 조립·검수·Ren'Py
출력만 담당한다.

- **배경**: 미리보기 패널 / 에셋 탭 배경 행의 **🖼 배경 업로드**. 배경 **이름**은 공유 라벨 — 같은
  이름을 쓰는 모든 장면에 한 번의 업로드로 적용된다.
- **캐릭터 스프라이트**: 에셋 탭 표정 썸네일의 **↥** (선택한 의상의 표정별 개별). 투명 배경 PNG 권장.
  같은 캐릭터·의상의 표정 세트를 각각 업로드한다.
- **CG**: 에셋 탭 **🎬 CG 컷** 섹션 — 같은 설명(`#CG`)을 쓰는 모든 장면에 한 번에 적용. 대본의 `#CG`
  위치부터 **장면 배경으로 전환**된다(팝업 아님) — 등장인물이 장면 끝까지 자동으로 숨겨지고, 원본이
  잘리지 않도록 블러 확대 배경과 합성되어 여백을 채운다(대사·성우 음성은 계속 진행). 같은 장면의
  두 번째 `#CG`는 배경만 교체.
- **아이템(소품)**: 에셋 탭 **🎁 아이템** 섹션 — 투명 컷아웃 PNG, 인게임 라이트박스 팝업 + "발견한 아이템" 보관함에 쓰인다.
- **BGM**: 에셋 탭 BGM 행 / 미리보기 패널의 **🎵 BGM 업로드**. Suno 기본 출력(mp3) 기준으로 파일명이
  고정된다. **업로드하지 않은 씬은 `play music` 자체가 나가지 않는다**(무음, 런타임 에러 방지) — 배경과
  달리 BGM엔 임시 대체가 없다. **재생 방식**(에셋 탭 BGM 섹션에서 토글): 기본은 같은 곡이 이어지는
  장면에서 끊기지 않고 계속 이어짐(다른 곡이면 항상 새로 재생) — 켜면 장면이 바뀔 때마다 같은 곡도
  처음부터 다시 재생. `#BGM`을 지정하지 않은 장면은 기본적으로 앞 장면의 곡이 그대로 이어짐 — 켜면
  그 장면에서 음악이 멈춤(단 `#BGM`은 적었지만 아직 업로드하지 않은 장면은 예외로 멈추지 않음).
- **메뉴 배경**: 에셋 탭 **🎬 타이틀 배경** 에서 **↥ 업로드**(타이틀 화면). 게임 중 ESC 메뉴 배경은
  **⎋ ESC 메뉴 GUI** 섹션의 "공통 배경"에서 별도로 올린다. 둘 다 없으면 테마색 그라데이션으로 폴백.
- **메인 메뉴 GUI(로고·버튼)**: 에셋 탭 **🖼 메인 메뉴 GUI** — 타이틀 로고와 메뉴 버튼 이미지를 올리면
  타이틀 화면이 그 이미지로 바뀐다(아래 "메인 메뉴 GUI" 절 참고). 안 올린 메뉴는 지금처럼 글자 버튼.
- **저장소 정리**: 에셋 탭 **🧹 저장소 정리** — 대본 수정·교체를 반복하며 쌓인, 어디서도 참조되지
  않는 업로드 파일을 스캔해 개수 확인 후 일괄 삭제한다(사용 중인 에셋은 건드리지 않음).

업로드 에셋은 IndexedDB 에 저장되어 ZIP·폴더쓰기·`.npproj.zip` 에 모두 포함된다.

### 배경: 이름은 라벨 — 같은 이름은 한 번만 업로드
배경 **이름**(이른 아침의 카페 등)은 여러 장면이 공유하는 라벨이다. 같은 이름을 쓰는 장면들은
배경을 한 번만 업로드하면 전부 반영된다. CG·BGM도 같은 방식(설명/이름 단위 공유)으로 동작한다.

### 성우(TTS) — Typecast 연동
대사 옆 **🎙 버튼**에서 보이스를 고르고 미리 들은 뒤 그 줄에 적용하거나, 캐릭터에
**"💾 캐릭터에 저장"** 해두면 에셋 탭에서 **그 캐릭터의 모든(미생성) 대사를 일괄 생성**할 수 있다.
- 브라우저 → 같은 오리진의 프록시(`/api/typecast`, 로컬은 vite dev 프록시)를 거쳐 Typecast API 를
  호출한다(BYO 키, CORS 우회 목적일 뿐 키는 저장하지 않고 그대로 통과).
  화면에 **잔여 크레딧**(플랜명 포함)이 표시된다.
- 생성 결과는 새로고침해도 잃지 않도록 자동 저장되고, 이미 만든(다운로드한) mp3 는 재생성 없이
  재적용할 수 있다(크레딧 절약).
- 일괄 생성은 요청 폭주(HTTP 429)를 피하도록 순차 처리된다.
- Ren'Py 로 내보낼 때 `game/voices/{언어}/*.mp3` 로 배치되고 대사에 `voice` 태그가 붙는다.

**비용 최적화 (에셋 탭 🎙 성우(TTS) 비용·검수)**
- **💡 비용 계산**: Typecast 는 "1글자 = 1크레딧"으로 과금이 고정돼 있어, 대상 대사의 글자수를
  더하기만 하면 정확한 크레딧이 나온다 — **API 호출 없이 즉시**(키가 없어도 계산 가능), 2000자
  초과로 실패 가능한 대사는 경고 표시된다.
- **🎙 전체 캐릭터 일괄 생성**: 보이스 프리셋이 저장된 모든 캐릭터의 남은 대사를 한 번에 생성한다.
  크레딧이 중간에 소진(HTTP 402)되면 그 시점에 멈추고, 이미 만든 대사는 다시 만들지 않으므로
  크레딧을 채운 뒤 같은 버튼으로 이어받기하면 된다.
- **▶ 미리듣기(목소리 오디션)**: 감정 프리셋(스마트/happy/sad 등)·강도를 바꿔가며 실제로 짧게
  생성해 들어본다(Typecast 보이스 목록엔 사전 녹음 샘플이 없어 소액 크레딧이 든다). 같은 설정
  조합(보이스·모델·감정·강도+텍스트)으로 다시 열면 **캐시에서 재청취는 크레딧 0**이다.
- **🎧 검수 시작(연속재생)**: 생성된 음성을 장면 순서대로 이어 들으며 검수한다. 배속(1×/1.25×/1.5×)
  조절, 화자 필터, 마음에 안 드는 대사는 **🔁 재생성 예약**으로 표시해두면 다음 일괄 생성 때 자동으로
  다시 만들어진다.

## 기기 간 작업 이동 (내보내기 / 가져오기)

작업물(장면·에셋)은 브라우저 로컬 데이터(localStorage + IndexedDB)라 기기마다 분리된다.
왼쪽 패널 **📤 내보내기**로 단일 파일(`<제목>.npproj.zip`)을 저장하고, 다른 기기에서 **📥 가져오기**.

- `.npproj.zip` 안에 `project.json`(장면·캐릭터·설정·에셋 메타) + `assets/`(업로드 파일) 가 모두 담겨 **업로드한 에셋까지 그대로 복원**된다.
- API 키(OpenAI)는 보안상 파일에 **포함되지 않는다**. 새 기기에서 다시 입력.

## Ren'Py 빠른 반복 (폴더 직접 쓰기)

Chrome/Edge 데스크톱에서 **Ren'Py 탭 → "⚡ 폴더에 쓰기"** 로 **프로젝트들의 부모 폴더**(런처 projects 디렉터리)를 한 번 연결하면, 이후 버튼 클릭만으로 생성 파일을 직접 기록한다. 기록 후 게임 창에서 **Shift+R**(리로드)로 즉시 반영.

- 위치: `<연결 폴더>/<프로젝트 제목>/game/...`. 매 동기화마다 `game/` 을 비우고 새로 써서 **낡은 파일이 안 남는다**.
- 폴더 핸들은 IndexedDB 에 저장되어 새로고침 후에도 재사용. 미지원 브라우저는 ZIP 다운로드 사용.

## GUI 테마 (장르 프리셋 · AI 테마 스튜디오)

내보내는 프로젝트는 **자체 제작 풀 GUI**를 포함. 기본값에서는 메뉴 배경 외 인터페이스가 전부 코드(Solid) 기반이라 외부 GUI 이미지 의존이 없다(메뉴 배경 미업로드 시 테마색 그라데이션으로 대체). 타이틀 로고·메인 메뉴 버튼만 업로드하면 그 이미지로 교체된다.

- **장르 프리셋 5종**: 로맨스·공포·SF·스릴러·일상. 좌측 **프로젝트 설정 → GUI 테마**에서 선택.
- **AI 테마 스튜디오**: 분위기/요청 입력 → **✨ AI 테마 생성**. AI 는 **테마 데이터(JSON)만** 출력하고 결정적 컴파일러가 유효한 `gui.rpy`/`screens.rpy` 로 변환(명암대비 강제 보정으로 가독성 보장). 키 없이도 시드 기반 변형 동작.

### 메인 메뉴 GUI — 타이틀 로고 · 버튼 이미지 (에셋 탭 🖼 메인 메뉴 GUI)

타이틀 화면의 게임 제목 글씨와 글자 메뉴를, 외부에서 만든 **이미지**로 갈아끼우고 **배치를 프리셋으로 고른다**.
게임마다 배경·로고가 달라지므로 앱이 그리지 않고 **업로드 슬롯**으로 받는다. 하나도 안 올리고 프리셋도
안 바꾸면 기존 글자 메뉴 그대로다(회귀 없음).

#### 🎨 배치 프리셋 5종

상용 비주얼노벨 타이틀 화면들에서 뽑은 배치 축. 카드로 고르면 좌표·문구 기본값이 채워지고, 그 위에
자유롭게 조절한다. **업로드한 버튼 이미지가 있으면 이미지가 우선**이고 프리셋은 위치·방향·간격·마커를 담당하므로,
"이미지 버튼을 하단 가로로" 같은 조합도 된다.

| 프리셋 | 배치 | 특징 |
|---|---|---|
| **좌측 세로** (기본) | 좌측 세로 1열 | 지금까지의 배치. 이미지 버튼 + 마우스오버 이동 |
| **하단 가로** | 화면 하단 가로 1줄 | 항목마다 **제목 + 설명 2줄**, 항목 폭 270px 고정(긴 문구는 줄바꿈) |
| **우측 2줄** | 우측 세로 | **영문 주 + 한글 부**, 주/부 글꼴을 다르게 |
| **우측 마커** | 우측 세로 | 마우스오버 시 **▶** 등장 + 강조색 하이라이트 |
| **렌파이 기본** | 좌측 세로 | 장식 없는 단순 텍스트, 로고는 우하단 |

- **✏️ 메뉴 문구 편집**: 슬롯마다 주/부 라벨을 고칠 수 있다. 비워두면 프리셋 기본 문구를 쓴다
  (부 라벨 칸은 2줄 프리셋에서만 나온다).
- **🔤 메뉴 글꼴**: 주/부 폰트를 따로 고른다(폰트 카탈로그 공용). 미지정이면 본문 폰트를 따라간다.
- **🖍 글자 외곽선**(기본 켜짐): 배경 그림이 밝아도 메뉴 글자가 읽히도록 검은 외곽선을 넣는다.
  어두운 아트에 거슬리면 끈다.

- **📦 한 번에 업로드**: 파일 여러 장(또는 폴더 통째)을 골라 **파일명으로 자동 매칭**한다 —
  `GUI_처음부터_기본.png` 처럼 슬롯(처음부터·이어하기·불러오기·환경설정·갤러리·게임 종료)과
  상태(기본·마우스오버·비활성화) 이름이 들어 있으면 알아서 제자리에 들어간다. 인식 못한 파일은 알려준다.
- **슬롯별 개별 업로드**: 6슬롯 × 3상태 그리드에서 한 칸씩 교체·해제.
- **타이틀 로고**: 업로드 후 X·Y·너비 지정(1920×1080 기준 px). 로고를 올리면 제목 텍스트는 안 나온다.
- **배치 조절 + 미리보기**: 버튼 열의 가로 위치·세로 시작·간격·마우스오버 이동을 px 로 조절하고,
  업로드한 타이틀 배경 위에 실제 좌표 그대로 축소해 보여준다(Ren'Py 를 켜지 않고 시안과 대조 가능).
  미리보기는 프리셋의 정렬·방향·2줄 라벨·마커·글꼴·외곽선까지 그대로 반영한다.
- **권장 규격**: 버튼 420×78 투명 PNG. 버튼 높이 78 + 간격 12 = **행 간격 90px** 이라 기본값
  (X 96 / Y 350 / 간격 12)이 그대로 스펙 좌표가 된다.
- **이어하기**는 저장 데이터가 없으면 자동으로 **비활성화 이미지**로 표시되고, 세이브가 생기면 활성화된다.
- **갤러리** 버튼은 아이템·CG 갤러리가 둘 다 있으면 선택 화면으로, 하나뿐이면 그 갤러리로 바로 간다.
- 이미지 없는 메뉴(정보·크레딧·도움말)는 버튼 아래 작은 글자 링크로 남는다.

> ⚠️ **클릭(눌림) 이미지는 쓰이지 않는다.** Ren'Py 의 `imagebutton` 상태는
> idle/hover/selected/insensitive 뿐이고 "누르고 있는 중" 상태가 엔진에 없다 — 누르는 동안엔 마우스오버
> 이미지가 그대로 보인다. 그래서 앱도 클릭 상태는 업로드 칸을 만들지 않는다.

### 인게임 GUI — 대사창·폰트 (좌측 AI 테마 스튜디오)
- **대사창 그라데이션**(새 프로젝트 기본 켜짐): 단색 박스 대신 **위로 갈수록 투명해지는 세로 그라데이션**.
  경계선 없이 장면으로 자연스럽게 사라지는 시네마틱 대사창이다.
  - **하단 진하기**(기본 65%): 글자가 놓이는 아래쪽의 최대 진하기. 밝은 배경엔 높게.
  - **페이드 높이**(기본 45%): 페이드가 화면 아래 몇 %까지 올라오는지. 클수록 완만·시네마틱.
  - 색을 지정하지 않으면 **테마의 대사창 색**을 따라간다(밝은 테마=흰 그라데이션+어두운 글자,
    어두운 테마=검은 그라데이션+밝은 글자) — 자동으로 글자 대비가 맞는다.
  - 페이드를 길게 해도 **대사·이름의 화면상 위치는 그대로**다(배경만 위로 확장된다).
- **창 색·불투명도**(그라데이션 끔): 대사창/선택지 배경색과 불투명도 조절 — 반투명 단색 박스.
- **본문색/이름색**: 본문 글자색(예: 흰색)·화자 이름색(예: 포인트 컬러) 지정.
- **글자 외곽선**: 켜면 본문·이름에 외곽선(기본 검정, 색 지정 가능) — 밝은 배경 위 가독성↑.
- 값은 테마 위에 덮어써 빌드/내보내기에 반영되고, **우측 미리보기 플레이어에도 같은 모양으로** 나온다
  ("기본값"으로 초기화 가능).

## 다국어 자막 · 음성

자막(글) 언어와 성우 음성 언어는 **완전히 독립적으로 교차 선택**된다(예: 자막은 한/영, 음성은 한국어만).

- **자막**: 대본에 `#설정_글언어`(또는 엑셀 `글언어:`) 태그로 지정하거나, 태그 없이도 대사·지문에
  번역만 채워두면(엑셀 C열=영어, D열=일본어) 자동으로 그 언어가 인게임 전환 목록에 포함된다.
  대본 원문(base) 언어가 항상 첫 번째로 고정.
- **음성**: `#설정_목소리언어` 태그로 지정. 캐릭터별로 언어마다 다른 TTS 음성을 붙일 수 있다.
- 자막·음성 언어가 각각 2개 이상이면 게임 내 **설정 화면에 언어 선택 라디오**가 자동으로 생긴다.
- 자막 자동 번역은 OpenAI(`gpt-4o-mini`/`gpt-4o`)로 수행(`src/generators/translate/`), 언어 전환 시
  대사 기록(History)도 깨지지 않게 유지된다.

## 실시간 협업 (2인)

같은 프로젝트를 **방 코드**로 공유해 두 사람이 동시에 편집한다(Supabase 기반, last-write-wins).

- 저장 시점마다(600ms 디바운스) 변경분을 동기화하고, 상대방의 커서 위치(현재 탭·선택 장면)를
  프레즌스로 표시한다. 내 타이핑이 아직 저장 대기 중일 땐 상대 변경 반영을 잠시 미뤄
  **입력 중 유실을 방지**한다.
- 방 코드를 아는 사람은 누구나 읽기·쓰기 가능 — **2인 신뢰 관계 전제**(접근 제어 없음, 코드 유출 시
  제3자도 편집 가능).
- ⚠️ **에셋(이미지·BGM·음성)은 그보다도 넓게 열려 있다.** anon 키는 설계상 JS 번들에 구워져 공개되고,
  RLS 정책이 전부 개방이며 Storage 키가 `<assetId>` 평면 구조라 방 단위 구분이 없다 — 즉 **배포 URL을
  아는 사람은 누구나 버킷 전체를 목록 조회·다운로드·업로드·덮어쓰기** 할 수 있다. 실질 방어선은 배포
  URL의 비공개성뿐이다. 사설 2인 도구라 감수한 선택이며, 민감한 자료는 올리지 말 것. 자세한 내용과
  뒤집는 방법은 [`supabase/setup.sql`](./supabase/setup.sql) 머리 주석 참고.
- Supabase 프로젝트 연결은 빌드 시점 설정(앱 배포자가 구성)이며, 사용자가 키를 입력하는 BYO 방식이 아니다.
- 셀프호스트/재구축 시 테이블·RLS 정책·Storage 버킷은 [`supabase/setup.sql`](./supabase/setup.sql)을 SQL Editor에서 실행해 구성한다(재실행 안전).
- 이미 운영 중인 Supabase 프로젝트를 새 버전 앱으로 올릴 때도 배포 전에 `setup.sql`을 다시 실행할 것
  (예: `projects.client_id` 컬럼 추가 — 없으면 저장이 400으로 실패한다).

## 입력 포맷

### 텍스트 (왼쪽 패널 직접 입력)
```
장면: 맑은 아침, 운동장
배경: 학교 운동장
BGM: morning_breeze
연출: 햇살이 환하게 비추는 아침

주인공(기쁨): 야, 오늘 날씨 진짜 좋다!
(잠시 두 사람은 말없이 서 있었다.)
선택지:
> 앞자리에 앉는다.
> 창가 자리에 앉는다. -> 다른 장면 제목
```

### 엑셀 (.xlsx)
A열 = 화자 이름, B열 = 대사 · 지문 · 태그.
- A열 있음 → 대사 / A열 없고 일반 문장 → 지문(나레이션) / A열 없고 `#`·`>` 시작 → 태그·선택지

| 태그 | 의미 |
|---|---|
| `#S 제목` | 새 장면 시작 |
| `#배경 이름` | 배경 직접 지정 (한 장면에서 바뀌면 자동 분할) |
| `#BGM 파일명` | BGM 지정 (이름 공유 라벨 — 업로드는 에셋 탭에서) |
| `#복장 캐릭터:의상` | 이 장면의 캐릭터 의상 (여러 명은 쉼표: `한지수:수영복, 강민주:교복`) |
| `#연출 내용` | 연출 노트 (ChatGPT 프롬프트 작성 참고용) |
| `#CG 설명` | CG 컷 |
| `#아이템 이름`(`#소품`도 가능) | 아이템(소품) 팝업 (`#아이템끝`/`#소품끝` 으로 닫기) |
| `#점프 장면제목` | 해당 장면으로 점프 |
| `#끝` | 분기 엔딩(다음 라벨로 새지 않고 종료) |
| `> 텍스트 -> 대상장면` | 선택지 (대상 생략 시 다음으로 진행) |

- `#배경/#BGM/#복장/#연출/#CG` 는 바로 위 `#S` 장면에 적용(`#복장`을 장면 도중에 적으면 **다음 대사/지문 줄부터** 적용 — 위 "의상" 절 참고). 한 장면 안에서 **배경이 바뀌면 자동으로 장면이 분할**된다(중간 빈 줄은 무시) — 이때만 의상이 다음 비트로 이어진다. `#S` 로 새 장면이 시작되면 의상은 초기화되므로, 장면마다 반복하지 않으려면 배경 키워드 규칙(에셋 탭)을 쓴다.
- **표정**: `주인공(기쁨): 안녕!` (커스텀 표정 이름도 인식) / **합동 대사**: `한지수, 강민주: 짠!`
- **표정·의상은 앱 [에셋] 탭에서 추가·이름변경**할 수 있다(엑셀엔 대본만, 설정은 앱에서).

### 대본 수정·재업로드 (병합)
이미 장면·에셋이 있는 프로젝트에 엑셀/텍스트를 다시 분석하면 **반영 방식을 고르는 모달**이 뜬다:
- **🔀 스마트 병합(추천)** — 엑셀/텍스트가 최신 전체 대본일 때. 배경·BGM·CG는 **이름 기준으로 업로드
  에셋이 자동 재연결**되고, 내용이 같은 장면·대사는 번역·표정·음성·승인 상태를 그대로 승계한다
  (`유지 N · 추가 N · 제거 N` 미리보기 표시, 새 대본에 없는 장면은 삭제). 장면 **제목이 바뀌었어도
  대사가 절반 이상 겹치면** 같은 장면으로 보고 승계한다(제목만 살짝 고친 경우 대비). 같은 대사의
  번역을 엑셀 C/D열에서 고쳐 오면 **엑셀 값이 우선** 반영된다.
- **➕ 뒤에 추가** — 새 장면만 담은 파일일 때. 기존 장면은 건드리지 않고 뒤에 붙인다.
- **♻️ 전체 교체** — 처음부터 다시(기존 장면·에셋 연결이 사라진다).
- 모달에는 **새 대본/기존 장면 수**가 함께 표시되고, 기존 장면이 여럿인데 새 대본에서 장면이
  1개만 인식되면(장면 태그 `#S`/`장면:` 누락 의심) **경고**가 뜬다.

## 배포 (실행 파일 만들기 + 개발 파일 제외)

내보낸 Ren'Py 프로젝트는 런처 **"Build Distributions"** 로 Windows/Mac/Linux/Web 독립 실행본을 만든다.

- 생성되는 `game/options.rpy` 에 **개발용 파일 제외 규칙(`build.classify`)** 이 들어 있어, 빌드 시
  원본 아트(psd/psb/ai/xcf/kra/clip)·기획서(docx/xlsx/pptx/hwp)·`dev/`·`docs/`·`기획/` 폴더·편집기 임시/백업/숨김 파일이 **배포판에서 자동 제외**된다.
- 개발용 파일은 프로젝트 안 `dev/` 폴더에 모아두면 한 번에 걸러진다.
- `game/credits.rpy` + 자체 GUI 의 **크레딧 화면**으로 에셋 출처·라이선스를 게임 안에 표기(엔진·나눔고딕 라이선스는 자동). 좌측 **프로젝트 설정 → 크레딧/라이선스 고지** 에 입력.

## 보안 / 라이선스 메모

- **100% 클라이언트 사이드**(백엔드 0). BYO 키 모델 — OpenAI 키는 localStorage 에만 있고 `api.openai.com` 으로만 HTTPS 전송. 생성 프로젝트·`.npproj.zip` 에 **키가 들어가지 않는다**. XSS 싱크 없음(React 자동 이스케이프, `dangerouslySetInnerHTML`/`eval` 미사용).
- OpenAI 는 브라우저 직접 호출(CORS 허용)이라 dev 프록시가 필요 없다. Typecast(TTS)는 CORS 미허용일
  수 있어 같은 오리진 프록시(`/api/typecast`)를 거치지만, 키는 저장 없이 그대로 통과시킬 뿐이다.
- **xlsx(SheetJS)** 는 npm 0.18.5(Prototype Pollution·ReDoS) 대신 **SheetJS 공식 CDN 패치판(0.20.3)** 사용.
- 의존성 라이선스: React/zustand MIT, xlsx Apache-2.0, jszip MIT(듀얼) — 모두 상업적 사용 가능.
- ⚠️ 향후 **당신의 키를 제공하는 호스팅 모델**로 바꾸면 키를 절대 클라이언트에 두지 말 것(백엔드 프록시 필요).

## 검증

```bash
npm run typecheck   # 타입 검사
npm run test        # vitest 단위/통합 테스트 (239개)
npm run build       # 타입체크 + 프로덕션 빌드

npm run gen:lint    # 샘플 대본 → .lint-tmp/ 에 실제 .rpy + 참조 이미지 스텁 생성
                    # 이후: renpy.exe .lint-tmp lint
npm run test:e2e    # Playwright 풀 파이프라인(분석→업로드→ZIP 내용 검증)
                    # 먼저 npm run build && npm run preview (4173) 가 떠 있어야 한다
```

> `tests/zip-asset-invariant.test.ts` 가 **"생성된 `.rpy` 가 참조하는 에셋 경로 = ZIP 에 실제로 들어가는
> 파일"** 불변식을 지킨다(메뉴 프리셋·커스텀 폰트·일본어 로케일·그라데이션 매트릭스). 이 불일치는
> 타입체크도 `lint` 도 못 잡고 게임 실행 순간 크래시하므로, 새 에셋 출력 경로를 추가하면 이 테스트
> 매트릭스에도 반드시 추가할 것.

> Ren'Py `lint` 는 런타임 화면 오류를 다 잡지 못한다. GUI/화면 변경 시 실제 Ren'Py 에서 메뉴·인게임을 클릭하는 런타임 스모크 테스트를 권장(크레딧 화면 추가 등).
